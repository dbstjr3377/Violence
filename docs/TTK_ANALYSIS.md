# 짧은 TTK 분석: 게임이 지루해질 수 있는 경우

VIOLENCE의 전투는 TTK(처치까지 걸리는 시간)가 매우 짧습니다. 이 문서는 그 영향을 숫자로 확인하고, 플레이가 단조로워지거나 지루해질 수 있는 경우를 정리합니다.

- 근거 1: 플러그인 코드와 `weapons.yml`, `config.yml`의 실제 값
- 근거 2: 매치 시뮬레이션 `tools/ttk_sim.py`
  - 실제로 생성된 맵 5종(클럽·교도소·아파트 A·하수구·식당)의 보행 칸과 시야(복셀 광선)를 씁니다.
  - 전투 규칙은 플러그인 값을 따릅니다.
  - 플레이어 8·16·24명 × 두 번씩, 모두 30판을 돌렸습니다. 설정 변경 비교는 교도소·하수구에서 따로 30판을 돌렸습니다.
  - 0.25초 단위로 단순화한 모델입니다. 문, 유리, 가면 능력, 사람마다 다른 실력은 넣지 않았습니다. 그래서 절대값보다 경향을 보는 용도입니다.
- 실제 서버 데이터가 아니므로, 인게임 테스트에서 같은 지표(아래 "측정 제안")로 확인하는 것을 권합니다.

## 1. 현재 TTK

| 상황 | 처치까지 | 근거 |
|---|---|---|
| 머리 명중 | 즉시 | 머리 = 즉사 |
| 산탄총 / 더블배럴 | 즉시 | 한 발에 펠릿 12~28개 → 첫 펠릿에 쓰러지고 다음 펠릿에 사망 |
| UZI · MP5 · M16 몸통 | 33 / 50 / 70ms | 몸통 = 쓰러짐, 쓰러진 적에게 한 발 더 = 사망. 연사 간격 한 번 |
| 소음 권총 / 매그넘 몸통 | 약 170 / 400ms | 단발 (클릭 한도 초당 6회) |
| 근접 무기 · 맨주먹 | 0.25 ~ 0.9초 | 첫 타 쓰러짐 → 다음 타 또는 처형 |
| NPC가 나를 발견하고 첫 공격까지 | 0.45 ~ 0.95초 | 반응 6+(1-실력)×14+0~4틱 |
| 사람 반응 | 약 0.25 ~ 0.4초 | 일반적인 반응 속도 |

몸통에 맞아도 바로 죽지 않고 3초 쓰러짐이 있습니다. 하지만 같은 사람이나 근처 적이 0.1~0.5초 안에 끝내는 경우가 대부분이라, 실질 TTK는 "첫 명중 = 사망"에 가깝습니다. 먼저 본 쪽이 거의 항상 이깁니다.

## 2. 시뮬레이션 결과 (기본 설정, 30판 평균)

| 지표 | 값 | 뜻 |
|---|---|---|
| 게임 길이 | **2.5분** (모든 판이 목표 30킬로 끝남) | 제한 시간 10분의 1/4 |
| 사람 분당 킬 / 데스 | 7.6 / 4.4 | 8초마다 처치, 14초마다 사망 |
| 생존 시간 중앙값 | 8.4초 | |
| 처치 방식 | **처형 97%**, 총 3% | 쓰러뜨림 → 처형이 거의 유일한 마무리 |
| 맨손으로 보낸 시간 | **57%** | 총을 든 시간은 2% |
| 적을 못 찾는 시간 (탐색 공백) | 중앙값 3.2초, 상위 10% 12초 | 하수구는 중앙값 6.3초, 상위 10% 21초 |
| 보지도 못한 적에게 죽음 | 14% (8명 12% → 24명 16%) | 인원이 많을수록 늘어남 |
| 리스폰 3초 안에 죽음 | 3% | 리스폰 위치 선정이 잘 작동 |
| 사람 K/D | 1.8 (8명 2.1 → 24명 1.5) | NPC는 사람보다 훨씬 약함 |
| 사람이 잡은 킬 중 사람 비율 | 8명 14% → 24명 47% | 적은 인원에서는 대부분 NPC 사냥 |
| 한 판당 가면 선택 | 1인당 3.4회 | 연속 3/5킬이 흔함 |

맵별 차이는 작았습니다. 게임 길이 2.2~2.8분, 분당 킬 7.0~8.3이었습니다. 예외는 하수구로, 탐색 공백이 다른 맵의 2배 이상입니다.

## 3. 지루해질 수 있는 경우

### ① 무기가 바닥나면 맨주먹 난투만 남음 (가장 큼)
- 바닥 무기는 시작할 때 `인원 × 0.5 = 25개`뿐이고 다시 생기지 않습니다(`GroundWeaponService`).
- 가중치상 그중 총은 약 6자루(전체 총알 약 90발)입니다. 재장전이 없고, 빈 총은 사라집니다.
- 시뮬레이션에서 사람이 총을 든 시간은 2%였고, 맨손 시간이 57%였습니다.
- 경기 초반 1분이 지나면 총·연사·궤적·탄피 같은 슈터 요소가 거의 사라집니다. 대신 "주먹으로 쓰러뜨리고 처형" 반복이 됩니다.
- 무기 비율을 1.0으로 올려도 맨손 시간은 55% → 46%로만 줄었습니다. 무기 수보다 **보충이 없다**는 점이 원인입니다.

### ② 처치 방식이 하나로 수렴 (처형 97%)
- 맨주먹도 덩치가 아니면 한 방에 쓰러뜨립니다. 쓰러진 적은 처형하거나 한 대 더 치면 죽습니다.
- 그래서 무기가 달라도 결과가 같습니다. 근접 무기 14종의 마무리 시간은 모두 0.25~0.9초입니다.
- 처형 연출(카메라 전환, 맨손 4회 클릭)을 1분에 7번 이상 보게 되어, 연출의 무게가 빨리 닳습니다.
- 점수표의 무기별 차등(총 100 ~ 처형 500)도 의미가 줄어듭니다. 거의 모든 킬이 처형 500점이기 때문입니다.

### ③ 게임이 너무 빨리 끝남 / 선두 독주
- 목표 30킬은 평균 2.5분이면 나옵니다. 맵 준비와 카운트다운(10~20초)에 비해 본게임이 짧습니다.
- 가장 잘하는 한 명이 2분대에 끝내므로, 늦게 붙은 사람이나 많이 죽은 사람은 따라잡을 시간이 없습니다.
- 10분 제한 시간과 설정이 어긋나 있습니다. 시간이 다 돼서 끝나는 판이 사실상 없습니다.

### ④ 적은 인원(8명)에서는 NPC 사냥터
- 사람 반응이 NPC보다 2~3배 빠르고, NPC는 퍼짐 배율이 2~2.6배입니다. 그래서 사람 K/D가 2를 넘습니다.
- 8명일 때 사람이 잡은 킬의 86%가 NPC입니다. 위협이 적어 긴장감이 떨어집니다.
- NPC 반응을 더 느리게(1.5배) 하면 K/D가 2.3으로 더 벌어집니다. 지금보다 쉬워지는 방향은 지루함을 키웁니다.

### ⑤ 큰 맵(하수구)의 빈 시간
- 하수구는 108×108로 가장 큽니다. 적을 못 찾는 시간이 중앙값 6.3초, 상위 10%는 21초입니다.
- TTK가 짧아서 교전은 순식간에 끝나고, 나머지는 걷기입니다. 교전과 빈 시간의 대비가 커집니다.

### ⑥ 모르고 죽기
- 사망의 14%가 직전 1초 안에 보지 못한 적에게 당한 것입니다. 24명이면 16%입니다.
- 첫 명중 = 사망이므로 대응할 틈이 없습니다. "억울한 죽음"이 반복되면 이탈 요인이 됩니다.
- 리스폰 직후 죽음은 3%로 낮습니다. 리스폰 보호(1.5초)를 넣어도 거의 변하지 않았으니 지금은 필요하지 않습니다.

### ⑦ 연속킬 보상의 인플레이션
- 1인당 한 판에 가면 선택이 3.4회 나오고, 최고 연속킬 중앙값이 5.7입니다.
- 붉은 화면, 심장 박동, 가면이 "특별한 순간"이 아니라 거의 늘 켜진 상태가 됩니다.

### ⑧ 무기 개성의 약화
- 모든 총이 "몸통 두 발"이면 끝나므로, 연사 속도와 탄 퍼짐 차이가 체감되지 않습니다.
- 매그넘·권총은 두 번째 발까지 0.17~0.4초가 걸려 연사총보다 확실히 불리합니다(머리를 맞히지 않는 한).

## 4. 개선 제안 (효과가 큰 순)

| # | 제안 | 겨냥하는 문제 | 조정 위치 |
|---|---|---|---|
| 1 | **무기 보충**: 무기 지점이 비면 20~30초 뒤 다시 생성. 총은 매번 일정 비율 보장 | ①②⑧ | `GroundWeaponService.tick`, `config.yml`에 `weapon-respawn-seconds`, `gun-min-share` |
| 2 | **맨주먹은 넘어뜨리기만**: 덩치처럼 비틀거리게 하거나 두 대에 쓰러뜨림 (토니 가면만 예외) | ②⑧ | `CombatService.meleeHit` 맨주먹 분기 |
| 3 | **목표 킬을 인원에 맞춤**: 예) 목표 = 15 + 플레이어 수, 또는 제한 시간 5분 | ③ | `game.sk` `/게임시작` 기본값 |
| 4 | **쓰러진 적 사격 = 총 킬로 인정**, 처형은 점수·연출 보너스로만 | ② | 점수표 `score.sk` |
| 5 | **NPC 난이도 자동 조절**: 사람 K/D가 2를 넘으면 NPC 반응·명중을 올림 | ④ | `NpcManager` 반응 시간 식, `npc.skill-*` |
| 6 | **큰 맵 압박**: 오래 교전이 없는 사람에게 NPC 무리가 다가가거나 총소리 반경을 넓힘 | ⑤ | `NpcManager.hearNoise`, 맵별 설정 |
| 7 | **위협 신호**: 나를 조준하는 적의 총구 섬광을 크게, 등 뒤 발소리, 피격 방향 표시 | ⑥ | `Fx.muzzle`, HUD |
| 8 | **연속킬 문턱 상향**: 가면 3/5킬 → 4/8킬, 또는 시간이 지나면 연속킬 감소 | ⑦ | `streak` 로직, `score.sk` |
| 9 | **총 개성**: 권총·매그넘은 쓰러진 적에게 즉시 연사 가능(빠른 두 번째 발)하게, 연사총은 첫 발 퍼짐 증가 | ⑧ | `weapons.yml` `rpm`, `spread` |

설정만으로 해볼 수 있는 것(코드 변경 없음):
- 목표 킬: `/게임시작 club 50` 처럼 크게, 또는 `config.yml` `game.target-kills`
- 무기 수: `game.weapon-ratio: 1.0` (효과는 작음: 맨손 시간 55% → 46%)
- NPC 실력: `npc.skill-min/max` 상향

## 5. 인게임 측정 제안
시뮬레이션은 모델이므로, 실제 판에서 아래 값을 기록하면 판단이 정확해집니다(서버 로그나 Skript 훅으로 쉽게 남길 수 있음).
- 처치 방식 비율(총/근접/맨주먹/처형/던지기)과 무기를 든 시간 비율
- 게임 길이와 목표 달성 시각, 1위와 2위의 킬 차이
- 리스폰 후 첫 교전까지 걸린 시간 (탐색 공백)
- 죽기 직전 1초 안에 공격자를 화면에 봤는지
- 판당 가면 선택 횟수

## 6. 시뮬레이션 다시 돌리기
```bash
python3 tools/ttk_sim.py
```
```bash
python3 tools/ttk_sim.py --levers
```
결과는 `build-out/ttk/results.json`, `build-out/ttk/levers.json`에 저장됩니다. 맵 데이터(`build-out/maps/*.txt`)는 플러그인 테스트가 만듭니다.
